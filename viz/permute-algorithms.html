Three Ways to Realise a Permutation

Duijvestijn's permute (1972) · Haddon's cycle-sort (1990) · the shuffler's permute — one idea, three machines.

The problem, and the one idea

All three algorithms answer the same question: given an array and a permutation σ describing where each element must go, produce a sequence of primitive data movements that realises σ in place — no second array. And all three exploit the same structural fact: a permutation decomposes uniquely into disjoint cycles, and each cycle can be resolved independently, moving each element at most once (plus book-keeping).

Throughout this page every machine runs the same example: six elements a…f and the permutation σ = [2 3 4 1 0 5] (one-line notation, 0-indexed: the element at position i goes to σ(i)), which decomposes into a 3-cycle, a 2-cycle and a fixed point.

1 · Duijvestijn's permute — exchange and re-chase

BIT 12 (1972). Algorithm due to Windley; Duijvestijn supplies the invariant-based proof.

Convention alert: Duijvestijn's f points source-ward — f(k) is the position where the element destined for k currently lives (f = σ−1, and his arrays are 1-indexed). The algorithm scans k = 1…G. For each k it asks: where is my element now? It starts at f(k) and, if that position was already finalised (index < k), keeps chasing kn := f(kn) — each finalised position passes the buck to wherever its exchange pushed the displaced element. The chase stops at the first index ≥ k: that is ψk(k), the element's true current home. One exchange(VEC[kn], VEC[k]) finishes position k forever.

The loop invariant is E1 ∧ E2: positions below k are final (VEC[i] = αf(i) for i < k), and every pending element is parked exactly where ψk says it is. At k = 1, E1 is empty and E2 is the initial state; at k = G+1, E2 is empty and E1 is the theorem.

Cost: at most one exchange per position — exactly n − c exchanges (the Cayley optimum, 3 on our example). The price is the chasing: pointer hops are re-walked from scratch for every k, so index work can degenerate even though data movement is optimal.

2 · Haddon's cycle-sort — rotate through save

The Computer Journal 33(4), 1990. Shown here: special_cycle_sort (every key distinct, keys = home positions).

Haddon removes the re-chasing by walking each cycle once, carrying one element in a register. Scan i = 1…n; when the element at i is not home (its key j ≠ i), lift it into save and rotate: write save into its home, picking up the displaced element into save, and repeat until the displaced element's home is the hole left at i — the cycle closes. Elements move directly to their final positions: one write each, never an exchange.

The hand is outside the array — that is the whole difference from the other two machines. Entering a cycle costs nothing (save := a[i] is a register load), and a length-ℓ cycle costs ℓ+1 moves instead of 3(ℓ−1) for exchange-based rotation. His general_cycle_sort adds a histogram so duplicate keys each get a distinct home — the same problem the shuffler solves with equal-slot retagging.

Scanning finds every cycle because each non-unit cycle must contain an element above its home (a1 < a2 < … < ac < a1 being impossible); positions of finished cycles simply test as home and are skipped. Linear time, each element touched at most twice.

3 · The shuffler's permute — swaps through the stack top

libyul/backends/evm/ssa/stack/Shuffler.cpp, Emission::permute. The EVM's only primitive is SWAPn: exchange the top with the slot at depth n.

The EVM has no save register and no arbitrary exchange — every data movement must involve the top of the stack (a star transposition). So the top itself becomes the hand: while the top's slot is not home, swap it with its destination — that single swap places the top's slot and lifts the displaced one, which is Haddon's rotation step and Duijvestijn's exchange in one. When the cycle containing the top closes, the top tests as home; the algorithm then scans downward for any misplaced slot and pays one entry swap to merge the top into that cycle before walking it.

Cost per cycle: the cycle containing the top resolves in ℓ−1 swaps; every other non-trivial cycle costs its length + 1 (the entry toll) — on our example (3+1) + (2+1) = 7 swaps, versus the unrestricted optimum of 3 exchanges. Group-theoretically the entry swap merges the top's 1-cycle into the target cycle; every in-cycle swap splits a placed element off.

Two refinements the simulation below doesn't need (all values distinct) but the real code has: equal-slot retagging — equal values are interchangeable, so swapDestinations re-labels destinations instead of physically swapping equal slots, dissolving cycles that would only shuttle identical values (Haddon's histogram, done lazily); and the reach limit — SWAPn only reaches 16 deep, so a needed slot beyond reach aborts the attempt with Blocked, feeding the planner's victim-dropping loop. Neither ancestor has a failure mode; the EVM does.

The synthesis: the shuffler keeps Duijvestijn's primitive (exchanges are all the EVM offers) and Haddon's single-walk structure (no re-chasing — the working mapping is ψ, kept current by swapDestinations), and adds what neither ancestor needed: an entry toll, because its hand is part of the array, and a bail-out, because its arm is only sixteen slots long.
